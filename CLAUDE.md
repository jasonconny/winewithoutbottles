# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Wine Without Bottles — a web-based art project by Jason Conny that translates Grateful Dead setlists into abstract striped SVGs (each stripe = a song; color derived from the title, width from duration). The site is one "vessel" for the work. Current surfaces: the homepage hero (`src/routes/Home.tsx` — a random striped piece under the brand logotype, with the global nav), the reader (galleries + show pages), and a hidden `/builder` easter-egg route that ports the original manual SVG generator. The core algorithm ("the machine") lives framework-free in `src/wwob/`.

## Commands

See `package.json` scripts; Node version is pinned in `.nvmrc`.

`lint` and `typecheck` are separate steps: ESLint does not type-check, and `tsc` does not run lint rules. Run both.

`npx vitest run` runs the suite once (CI-style) — `npm test` is Vitest in **watch** mode, which will hang a non-interactive session.

## Architecture

Vite + React 19 + TypeScript SPA, migrated from Create React App.

- **Entry flow**: `index.html` (project root, not `public/`) loads `src/index.tsx`, which mounts a `<RouterProvider>` (`createBrowserRouter` over the routes in `src/router.tsx`) via React 19's `createRoot` into `#root`. Static assets live in `public/` and are served from `/`.
- **Import alias**: `@/` resolves to `src/` (configured in both `vite.config.ts` `resolve.alias` and `tsconfig.app.json` `paths`). Prefer `@/...` over deep relative imports; tests use it too (e.g. `import { routes } from '@/router'`).
- **Env vars**: only `VITE_`-prefixed vars are exposed to the browser via `import.meta.env`; they are PUBLIC (baked into the bundle) — never secrets. See `.env.example`; local overrides go in gitignored `.env*` files.
- **TypeScript** uses project references: `tsconfig.json` is a thin root that points to `tsconfig.app.json` (app code under `src/`, bundler resolution, strict) and `tsconfig.node.json` (the Vite config). Edit the appropriate child, not the root.
- **Testing** is configured inside `vite.config.ts` (not a separate Vitest config) — jsdom environment, globals enabled, with `tests/setup.ts` registering `@testing-library/jest-dom`. Tests use Testing Library and live in `tests/` (not co-located with source), importing from `../src`. They are type-checked because `tests` is in `tsconfig.app.json`'s `include`.
- **Styles** are SCSS (`sass`), imported directly into components (e.g. `Home.tsx` imports `./Home.scss`). No CSS modules or CSS-in-JS.
- **Data pipeline (offline generation)**: the "machine" is the framework-free `src/wwob/` module (`titleToRgb`, `durationToWidth`, `buildStripes`, `svgMarkup`). Show data is hand-authored in `data/shows/<year>/<id>.json` (id = `YYYYMMDD` — the compact date is also the show's URL; the `date` field stays ISO `YYYY-MM-DD` for display/sorting, and the validity test enforces id = date compacted **plus a two-digit ordinal on the dates that carry two shows** — see Early/late shows; organized into per-year subdirectories); `npm run generate` (`generator/generate.ts`, run via `tsx`, type-checked by `tsconfig.generator.json`, reads `data/shows` recursively) writes three kinds of output: per-show `public/shows/<id>.svg`, per-show `public/shows/<id>.json` (full `ShowDetail` incl. the setlist), and a light, songs-free index `src/data/shows.generated.ts` (`ShowSummary[]`) the app bundles. `ShowSummary` carries `durationSeconds` (total show length, summed at generate time) — the Gallery uses it for duration-proportional row widths. **The split matters for scale**: the bundled index stays small (~300 bytes/show) so the JS bundle is roughly flat as shows grow, while the heavy `songs` data is fetched per-show on demand (see Routing — the `/:id` loader fetches `public/shows/<id>.json`; Gallery/Home use only the in-bundle index). Pass filters (show id, filename, path, or quoted glob — e.g. `npm run generate 19770508`, `npm run generate '1977*'`) to rewrite only matching shows' per-show artifacts (SVG + detail JSON); the index is always rebuilt from every show so it stays complete and sorted. **Generated files are committed** (so CI needn't run the generator) and are eslint/prettier-ignored. The hand-authored data in `data/shows/<year>/<id>.json` is the **source of truth** and is freely editable for corrections (edit data → `npm run generate <id>` → commit; the `public/shows/<id>.svg` diff is the reviewable record). Reconstructing a legacy show from Jason's original 2013 SVGs is a `generator/verify.ts` bootstrap — see the `reconstruct-legacy-show` skill. The committed guard is `tests/data-validity.test.ts`, which keeps the authored data well-formed (id matches filename, valid `m:ss` durations, non-empty setlists, no duplicate ids) and the generated manifest's id set in sync with the data files.
- **Early/late shows** — on the nights the band played twice, clearing the house between performances (a 1970–71 habit; once the three-set night became the shape of a Dead show it was over), the date carries **two shows, not one**: two setlists, so two pieces of art, two files, two URLs. **Two separate mechanisms, deliberately not one.** (1) **`sitting?: 'early' | 'late'`** on `ShowMeta` is the fact — authored, optional, and **free-standing**: a date whose early tape is lost still has a knowable _late_ show, and it keeps a plain 8-digit id. This is what the UI reads. (2) **A two-digit ordinal on the id** (`1970021301`, `1970021302`) is _only_ a collision-breaker, present only when a date actually carries two shows; it says which of the night's shows this is and nothing more. An earlier pass encoded the label in the id itself (`19700213-early`) — that was replaced because it couldn't express a lone known-late show without implying a sibling, and it forced every display site to parse a URL to render a word. `date` stays plain ISO on both shows, so year/tour/venue/run galleries and release date-matching are untouched. Ids still sort lexicographically into performance order (`1970021301` < `1970021302` < `19700214`), which is why `generator/generate.ts` and `buildRuns` tiebreak on id after date rather than trusting file order. Shape lives once in `src/wwob/showId.ts`; `tests/data-validity.test.ts` enforces the whole contract per _date_ (lone date ⇒ no ordinal; 2+ shows ⇒ contiguous `01..N` ordinals, a `sitting` on each, and ordinal order agreeing with sitting order). Display: `sittingLabel` in `src/date.ts` renders `early show`/`late show` — **lowercase deliberately**, so it reads as a quiet qualifier on the date rather than a second proper noun beside the venue; the info sheet's `<h2>` appends it after the linked year (`February 13, 1970 · early show`), and the Show and Gallery `alt` text fold it in with a comma so two rows for one night don't read identically. The page title stays the bare id. First four: DP 4's 1970-02-13 and 1970-02-14 Fillmore East.
- **Sourcing shows from releases** — adding a show, retiming one, the song-title canon (`data/songs.json`), the official-release index (`data/releases.json`), the importer (`generator/import.ts`), staged partials (`data/partial-shows/`), shows whose setlist can't be known (`data/unknown-setlists/`), release tags, and `source` on `ShowFile`: see the **`import-show` skill**. The short version — show data is authored in `data/shows/<year>/<id>.json` and drafted from the release that carries it (`tsx generator/import.ts <id> --write`, which leaves venue/city blank to fill in by hand); every song title must already exist in `data/songs.json`, and **adding one is deliberate**, because `cleanTitle` makes a title's word content its colour, so a near-miss variant is a different stripe on the wall. `tests/data-validity.test.ts` enforces the whole contract, so a violation fails there with a message naming the fix.
- **Show metadata taxonomy** — three layers, no overlap. **Facets** are structural and drive galleries automatically: year (from `date`), `tour`, `venue`, and **run** (derived, see Routing). **Tags** (`tags?: string[]`) are the many-per-show layer for what no facet expresses, and they now come from **two sources**. The _editorial_ ones are authored by hand and stay sparse (`Dark Star`, `Wall of Sound`, `Live/Dead`, `Shows I Attended`, `Sunshine Daydream`, `Final Show`). The _release_ ones are applied from the show's **chosen source** in `data/releases.json` (`Get Shown the Light`, `Dave's Picks`, `Spring 1990 (The Other One)`, …) — 20 tags across 87 of 175 shows. Both head for **tag index pages, not drawer nav items**, and `tests/data-validity.test.ts` rejects any tag that restates the show's `date`/`tour`/`venue`/`city`, since a typo would mint a phantom index. The allow-list is now **half derived**: editorial tags are listed literally, release tags come from the index, so importing a batch from a new box doesn't mean remembering to widen a constant — but a tag no release grants still fails. Two rules keep release tags from being noise: a show takes the tag of its _chosen_ source only (most shows sit on two or three releases, and tagging from all would describe release history rather than group anything), and a tag is skipped when its release covers **exactly** a tour's date set — `Europe '72` covers all 22 shows of the `Europe 1972` tour, so its index would duplicate the tour gallery. **Two tours were renamed** to clear collisions with box names now used as tags: `June 1976` → `June 1976 Comeback` and `Spring 1990` → `Spring 1990 East Coast`, so `/june-1976` (tag) and `/june-1976-comeback` (tour) coexist. Gallery slugs derive from the registry at module load, so renaming a tour in the data is the whole change — nothing in `src/router.tsx` or `worker/routes.ts` names a tour. **Two tags are deliberate exceptions to "derivable ⇒ facet, not tag"** — authored by hand, but each pinned by a data-validity test so it can never drift out of sync, in either direction. Add a show and the tests tell you what it must carry. (1) **`Dark Star`** — tag ⇔ a song titled exactly `Dark Star` in the setlist (26 shows). It stays a tag because it's a special case, the song the project is built around, not the beginning of a per-song facet; per show, not per performance, so the 9 shows that play it twice (the post-drums reprise) carry one tag. Per-song indexes, linking each stripe to its song, would supersede it if they ever happen. (2) **`Wall of Sound`** — tag ⇔ `date` within `1974-03-23`..`1974-10-20`, the PA's debut at the Cow Palace through its last night at Winterland. Purely a date range: every show inside had the rig, and the early-1974 shows before the debut did not, so it is emphatically NOT "all of 1974". **The retired `collection` field** was a pre-gallery vestige transcribed from the 2013 FINAL folder names: redundant with `tour`/`venue`/run for 171 of 175 shows, and, being single-valued, the only thing that ever forced a "which grouping wins?" choice (facets never collide — one show is in its year, tour, venue _and_ run gallery at once). Curation is many-to-many, so it lives in `tags`. If curated Collections pages happen later, a collection should declare its members (a tag or an explicit id list) rather than each show declaring its one collection.

## Conventions

- **Mobile-first responsive design**: author base styles for the smallest viewport first, then layer complexity for larger screens with `min-width` media queries (not `max-width`/desktop-down). Favor fluid, relative units (`rem`, `%`, `vw`/`vh`, `clamp()`) over fixed `px` for anything that should adapt. Applies to all new and updated SCSS. Use the breakpoint system in `src/styles/_breakpoints.scss` (`@use` it, then `@include respond-to('md') { … }`).
- **Accessibility**: no formal WCAG conformance level is targeted, but stay mindful — semantic HTML, labeled form controls, visible focus states, never convey meaning by color alone, and respect `prefers-reduced-motion`. Deliberate exception: the homepage `<h1>` is a brand **logotype** rendered as an intentional low-contrast watermark over the artwork (WCAG 1.4.3 exempts logotypes from contrast); its accessible name is preserved via real `<h1>` text + the document `<title>`. Do not "fix" the heading's contrast — automated scanners (axe/Lighthouse) will flag it, and that is expected.
- Prettier with single quotes (`.prettierrc.json`) — run `npm run format` before committing.
- ESLint uses flat config with `typescript-eslint`, `react-hooks` (`configs.flat.recommended`), and `react-refresh`. Note the v7 react-hooks gotcha: the flat config lives under `reactHooks.configs.flat.*`; the top-level `recommended`/`recommended-latest` keys are legacy eslintrc format and will not load in flat config.
- Routing uses `react-router-dom` v7 (`createBrowserRouter` + `RouterProvider` in `src/index.tsx`); routes are defined in `src/router.tsx`. **Every route lives inside the `AppChrome` layout route** (nav drawer + chip bar; chrome state persists across navigation), homepage included: `/` is the layout's **index route** → `Home` (random-art hero + watermark logotype), which opts into chrome sleep like `Show`. The retired `/placeholder` holding page is gone — the URL now 404s via `/:id` (pinned by `tests/routing.test.tsx`), though `placeholder` stays in `RESERVED_SLUGS` so no gallery can claim it. `/all` → the all-shows Gallery, plus one **static route per gallery slug** (`/1977`, `/spring-1977`, `/madison-square-garden`, …) generated in `src/router.tsx` from the registry in `src/galleries.ts` — one `Gallery` component serves every gallery page (minimal/abstract: no text, 10vh stripe rows, widths duration-proportional with the page's longest show spanning the full pane). The registry derives years / tours / venues-with-≥`VENUE_MIN_SHOWS`-shows / **runs** from the bundled index at module load; gallery slugs share the root namespace with show ids, so it throws on duplicate, reserved (`all`/`about`/`builder`/`placeholder`/`gallery`), or show-id-shaped slugs (`isShowId`, guarded by `tests/galleries.test.ts`; venue names ambiguous across cities get city-suffixed slugs/titles, judged corpus-wide so slugs don't churn; a tour named after a bare year defers to the year gallery). **Runs** (`buildRuns`) are 2+ shows at one physical venue on _adjacent performance dates_: consecutive in the date-sorted corpus (so the band played nowhere else between) and ≤`RUN_MAX_GAP_DAYS` (3) apart, so **dark days don't split a stand** — MSG September 1988 is one 9-show run, not the three that naive date-adjacency would give. Titled `Venue Month Year` from the run's **first** show (three runs cross a month boundary, so the calendar month alone won't do). They're derived rather than authored precisely so they stay correct as shows are added, and they're the reason retiring `collection` lost nothing — `Winterland 1974`/`Fillmore West 1969` come back as runs. **Two lists, deliberately different**: `allSubGalleries` is every page that exists (what `src/router.tsx` and `worker/routes.ts` enumerate), while `gallerySections` is drawer nav only and **excludes runs** — 40 entries would swamp it, so a run is reached from the link on its shows' info sheets (`findRunForShow`). Adding a page family that isn't in the drawer means using `allSubGalleries`, or the edge will 404 pages the SPA renders. The drawer's sub-gallery links are data-driven from `gallerySections`, rendered as collapsible groups (Years/Tours/Venues) that start collapsed and are not mutually exclusive; expansion state is local to `ChromeShell` (persists across navigation like the rest of the chrome), and the collapsed panel is `inert` so its links stay out of the tab order while remaining animatable. `/:id` → Show, where the id is the compact show date, optionally plus a two-digit ordinal (e.g. `/19720827`, `/1970021301` — the shape lives in one place, `src/wwob/showId.ts` (`SHOW_ID_RE`/`isShowId`/`parseShowId`), which the router, the gallery slug guard, and `tests/data-validity.test.ts` all use; the `loader` fetches `public/shows/<id>.json` for the full detail; a non-id-shaped param or unknown id throws a 404 `Response`, rendered by the route's `errorElement`, the global `NotFound` page); `/about` → About; `/builder` → the unlinked (but chromed) builder easter egg; `*` → `NotFound` (multi-segment paths; chromed like every page). Page titles use the colon style `Wine Without Bottles: <Page>` (shows use the compact id, e.g. `Wine Without Bottles: 19720827`; galleries their title, e.g. `Wine Without Bottles: Spring 1977`; the 404 is `Wine Without Bottles: Not Found`); the bare-brand title stays on Home/`index.html`. **The home flip is done** — `/` was repointed from the placeholder holding page to the real homepage, which is the same hero plus the chrome's nav, exactly as planned. What remains deferred: prev/next on shows, setlist surfacing, and Collections pages.
- **Deploy**: Cloudflare Worker with Static Assets (not Pages) — see the `deploy` skill for the full setup and the CI auto-deploy job. `worker/index.ts` fronts the SPA fallback so unknown paths get a real 404 status instead of a soft-404; its route list (`worker/routes.ts`) is built from the same `src/galleries.ts` registry the router uses, and `tests/worker-routes.test.ts` pins it against `src/router.tsx`. **Adding a static route means adding it to `STATIC_PATHS` too** — that test will tell you.
